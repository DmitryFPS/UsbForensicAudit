## [Unreleased]

### Fixed
- Обычный список устройств скрывает отдельные записи букв дисков, меток и GUID
  томов, включая USB-тома, а также внутренние диски. Все исходные записи доступны
  через «Показывать все записи»; привязанные тома остаются в досье накопителя.
- Сопряжённые Bluetooth-устройства и самостоятельные следы DeviceClasses больше
  не подписываются как «Служебная запись Windows» и обрабатывают даты событий.
- WPD-запись USBSTOR определяется как накопитель, а не телефон. Один GUID тома
  WPD больше не считается доказательством внешнего USB-устройства. Службы
  Bluetooth и программные узлы контроллеров исключены из числа устройств.
- Проверка целостности обнаруживает усечение и удаление журнала доказательств,
  включая исчезновение последней сессии; CLI возвращает код нарушения.
- Сохранённые сессии восстанавливают сведения о привилегиях, эталонном образе
  и журналах NTFS. Старые базы обновляются без удаления данных.
- Устранены ложные объединения устройств по модели диска, повторному серийному
  номеру разных моделей, пустому ContainerID и общему USB-порту. Шаблонные
  и сгенерированные Windows номера не используются как аппаратные серийники.
- Снимок сети остаётся у сессии, из которой запущен. Мониторинг проверяет первый
  снимок после загрузки базы и отбрасывает результаты остановленного сеанса.
- Сетевые сеансы разных пользователей сохраняются раздельно; источник даты
  обновляется вместе с датой. Недоступный журнал NTFS не считается прочитанным.
- Офлайн-отчёты не хешируют одноимённые файлы с компьютера аналитика.
- Пакет доказательств корректно обрабатывает входной manifest.json и даты,
  выходящие за поддерживаемый ZIP диапазон.
- Сборка допускает установленный .NET SDK 10.0.400 через latestFeature.
- Добавлены 28 регрессионных сценариев, обновлены устаревшие проверки интерфейса
  и структуры Excel. Все 1439 тестов проходят, покрытие строк — 90,45%.
- Приложение не запускалось на Windows 10 22H2 сборки 19045.2486: висел курсор
  ожидания, окно не появлялось, `app.log` оставался пустым. Причина — apphost
  .NET 9+ по умолчанию ставит флаг `/CETCOMPAT`, и на процессорах с поддержкой
  CET (Intel Tiger Lake и новее, AMD Zen 3 и новее) в паре с `ntdll.dll` без
  исправления из KB5044273 CoreCLR завершает процесс через
  `RaiseFailFastException` (`0xc0000602`) ещё до показа окна — dotnet/runtime#110920.
  Проявилось при миграции на .NET 10: у всех прежних сборок на .NET 8 этого
  флага не было. В `Directory.Build.props` добавлен `CETCompat=false`; на код
  и логику анализа это не влияет, меняется один бит в PE-заголовке `.exe`.
- Опрос служб корпоративной защиты USB больше не выполняется в UI-потоке до
  показа окна. Обращение к WMI из заблокированного STA-потока останавливало
  цикл сообщений и упиралось в таймаут даже на исправной машине, из-за чего
  защита ошибочно считалась неактивной. Опрос вынесен в фоновую задачу
  (`EndpointProtectionEnvironment.BeginProbe`), результат забирается там, где
  он нужен, — при сканировании, в отчётах и при старте мониторинга. Время до
  готового окна сократилось с ~7,0 с до ~1,9 с.

### Added
- Диагностика запуска в `app.log`: обработчики исключений и журнал включаются
  первыми, до любой тяжёлой работы, поэтому сбой на недоступной машине больше
  не оставляет пустой файл. В начало пишется слепок окружения (версия сборки,
  путь к exe, размещение данных, рантайм, состояние CET у процесса, версия
  Windows со сборкой и UBR, версия `ntdll.dll`, процессор, права), далее —
  отметки этапов `STAGE` с временем от старта процесса. Последняя отметка
  указывает, на каком шаге приложение остановилось; время первой отметки
  показывает, сколько заняла распаковка single-file бандла.
- Журнал ведётся весь сеанс, а не только на старте. В `app.log` попадают
  действия оператора (`ACTION`) — нажатия кнопок, переключение разделов, выбор
  в списках, открытие окон — и копия журнала работы из окна (`UI`), который
  раньше жил только в памяти и пропадал вместе с окном. Обработчики
  зарегистрированы на уровне классов WPF, поэтому охватывают все окна сразу и
  новые элементы попадают в журнал без правок. Записи фильтров, которые
  элементы выставляют себе сами при построении интерфейса, отсекаются до первой
  отрисовки, чтобы не выдавать инициализацию за действия оператора.
- Завершение сеанса фиксируется: код выхода и длительность работы, отдельно —
  завершение сеанса Windows. Если процесс сняли или рантайм упал без шанса
  что-либо записать, на диске остаётся маркер `data\session.open`, и следующий
  запуск пишет в журнал `WARN` о нештатном завершении предыдущего сеанса.
  Иначе такой обрыв неотличим от штатного выхода.
- `scripts\launch-with-host-trace.cmd` — запуск с трассировкой загрузчика .NET
  (`COREHOST_TRACE`) в `data\host-trace.log`. Покрывает стадию до управляемого
  кода: apphost, `hostfxr`, `hostpolicy`, распаковку single-file бандла, где
  приложение и зависало и куда `app.log` дотянуться не может.
- Ротация журнала на 8 МБ с сохранением предыдущего файла в `app.log.1`:
  подробная запись всего сеанса не должна съедать место на съёмном носителе.

### Changed
- Миграция на .NET 10 LTS: таргет всех проектов `net8.0-windows` →
  `net10.0-windows`, SDK в `global.json` — `10.0.302`. Пакеты `10.x`
  теперь соответствуют рантайму; поддержка .NET 8 заканчивается в
  ноябре 2026 года.
- Удалены пакеты `System.Text.Encoding.CodePages` и
  `System.Diagnostics.EventLog`: в .NET 10 они входят в состав рантайма,
  явная ссылка вызывает ошибку NU1510.

### Added
- Файловые артефакты в офлайн-анализе (`OfflineUserFileArtifactCollector`):
  режим `--offline` теперь разбирает LNK-ярлыки каталога Recent и рабочего
  стола плюс Automatic/Custom Jump Lists каждого профиля исследуемого образа
  и отвечает на главный вопрос расследования — какие файлы открывали со
  съёмного носителя и кто именно. Переиспользуются боевые парсеры
  `ShellLinkParser` и `ForensicArtifactParsers`; исследуемые файлы только
  читаются; лимиты на профиль защищают отчёт от замусоривания.
- Алерт о неизвестном устройстве в live-мониторинге (`UnknownDeviceDetector`,
  окно `UnknownDeviceAlertWindow`): при старте мониторинга из доказательной
  базы загружается базовая линия идентичностей всех устройств прошлых
  сканирований (`IAuditStorage.ListKnownDeviceIdentities`, DISTINCT-запрос
  без загрузки полных сессий). Каждый снимок live-устройств сверяется с ней;
  устройство без совпадения по серийнику, VID/PID или DeviceInstanceId
  поднимает окно-алерт поверх остальных и запись в журнале GUI. Повторные
  алерты по одному устройству в рамках сеанса подавляются; хабы и
  контроллеры без серийника не считаются неизвестными.
- Локализация CLI (`CliStrings`, флаг `--lang ru|en`): все пользовательские
  сообщения консольной версии вынесены в ресурсы `Strings.resx` (русский —
  базовая культура, `NeutralLanguage=ru`) и `Strings.en.resx` (английская
  satellite-сборка). Язык по умолчанию наследуется от системы; `--lang`
  применяется до разбора остальных аргументов, поэтому даже ошибки парсинга
  печатаются на выбранном языке. Попутно исправлены повреждённые символы
  UTF-8 в справке CLI и README.
- Запечатывание сессий и верификация целостности (`EvidenceIntegrityVerifier`,
  CLI `--verify`): итоговый SHA-256-хеш каждой сессии сохраняется печатью в
  `audit.sqlite` (колонка `seal_hash`), а `--verify` пересчитывает hash-chain
  журнала `evidence.jsonl` запись за записью и сверяет печати. Любая правка,
  удаление или вставка записи задним числом обнаруживается с точностью до
  строки. Код возврата `4` — нарушение целостности; с `--json` сохраняется
  машиночитаемый отчёт верификации.
- Офлайн-анализ чужой системы (`OfflineWindowsAuditor`, CLI `--offline <корень>`):
  смонтированный образ диска или скопированный каталог Windows. Анализируются
  кусты SYSTEM (USBSTOR, USB, MountedDevices), SOFTWARE (Windows Portable
  Devices, дата установки ОС) и NTUSER.DAT профилей (MountPoints2). Кусты
  копируются перед загрузкой — исследуемые файлы не изменяются. Результат
  сохраняется в общую базу сессий с префиксом `offline-` и доступен для
  `--diff`, JSON-экспорта и генерации отчётов.
- Сравнение сессий сканирования (`SessionDiffService`): что появилось и что
  исчезло между двумя сохранёнными сканами — устройства, доказательства,
  признаки очистки, сетевые связи. Исчезнувшие доказательства помечаются как
  forensic-сигнал (возможная очистка следов или ротация журналов).
- CLI: `--list-sessions` — список сохранённых сессий из `audit.sqlite`;
  `--diff <базовая> <целевая>` — отчёт сравнения двух сессий, с `--json`
  сохраняется в файл. Оба режима работают без прав администратора.
- Порт `IAuditStorage.ListSessions()` — карточки сессий без полной загрузки.
- CLI-режим (`src/UsbForensicAudit.Cli`): headless-сканирование тем же
  конвейером `AuditOrchestrator`, экспорт результата в JSON (`--json`),
  генерация отчётов без GUI (`--reports`, `--formats`), коды возврата
  для скриптов и планировщика задач.
- Release-workflow (`.github/workflows/release.yml`): по тегу `vX.Y.Z` —
  сборка, тесты, аудит уязвимостей, публикация self-contained `win-x64`,
  zip-архив, `SHA256SUMS.txt` и GitHub Release с автогенерацией release notes.
- `LICENSE` — проприетарная source-available лицензия.
- `.editorconfig` — единый стиль кода C# для всего репозитория.
- `SECURITY.md` — политика сообщений об уязвимостях.
- `CONTRIBUTING.md` — правила участия в проекте.
- `CHANGELOG.md` — этот файл.

## [1.0.0] — не выпущено (текущая версия в csproj)

### Added
- GUI-first forensic-аудит USB/Type-C устройств для Windows 10/11 (WPF + MVVM).
- Конвейер сканирования из 20 шагов: реестр (USBSTOR, USB, SetupAPI и др.),
  журналы событий Windows, профили пользователей, USN Journal,
  артефакты запуска, браузеры, сети.
- Корреляция артефактов с устройствами и выявление признаков очистки следов.
- Отчёты HTML / PDF / Excel.
- Хранение сессий в SQLite (`audit.sqlite`) и доказательной цепочки
  с hash-chain SHA-256 в `evidence.jsonl`.
- Живой монитор подключённых устройств.
- Интеграция с Procmon.
- Portable-сборка (self-contained, single-file, win-x64).
- CI: сборка, 600+ тестов, coverage gate ≥90%, аудит уязвимостей,
  CodeQL, Dependabot, locked restore.
