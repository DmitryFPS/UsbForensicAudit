# Критерии готовности выпуска

Оценка зрелости не является процентом пройденных тестов. Отсутствие известных дефектов и прохождение CI не заменяют проверку взаимодействия с Windows и устройствами.

## Автоматический контроль

- Восстановление зависимостей в locked mode, Release-сборка с ошибками на предупреждениях, проверка форматирования.
- Весь набор тестов и порог покрытия строк 90% в существующей конфигурации. Исключения из покрытия должны быть видны при оценке результата.
- Проверка зависимостей: отказ источника данных или самой команды не считается успешной проверкой уязвимостей.
- Автономная публикация win-x64 и проверка ресурсов EXE.
- Регрессии неоднозначной привязки файлов, повторяющихся серийных номеров, конфликтующих VID/PID, пустых идентификаторов, разных пользователей и ограничения длины истории.
- NativeDeletionIntegrationTests выполняет реальные операции в частном файловом кусте через Windows API и синхронизирует настоящую SQLite-базу. Проверяет сохранность соседней ветви, содержимое резервной копии, отказ копирования, изменившиеся данные, ошибку протокола и отмену. Рабочий реестр Windows не используется.

## Приёмка на выделенной Windows-среде

Для подтверждения готовности функций удаления требуется изолированная Windows-машина или VM с USB passthrough, снимком системы и тестовыми носителями. Приёмка не должна удалять устройства и историю повседневного рабочего места.

1. Подключить два экземпляра одинаковой модели накопителя; отдельно телефон MTP, Bluetooth-устройство и USB/Type-C накопитель через мост UASP. Сохранить фактические идентификаторы и эталонный список подключений.
2. Просканировать с административными правами. Проверить источники, имена, состав групп, отсутствие объединения разных экземпляров, видимость ограничений сбора.
3. На тестовых носителях создать разные файлы, открыть их, последовательно назначить двум носителям одну букву. Убедиться, что неоднозначные следы не стали доказанными действиями на обоих устройствах.
4. Проверить множественный выбор, раскрытие групп, неподвижность горизонтальной прокрутки, поиск, фильтры, карточки и экспорт. Сопоставить текст главной сводки, PDF, HTML и XLSX.
5. Отключить один тестовый экземпляр. Сопоставить план удаления с известными путями реестра. Проверить отказ для подключённого устройства и компонентов других экземпляров.
6. Выполнить удаление выбранного экземпляра. Проверить резервные копии и протокол, повторно прочитать каждый поддерживаемый источник, проверить SQLite и сохранность соседних устройств.
7. Повторно просканировать, перезапустить приложение и Windows. Проверить частичный результат и явно обозначенные неподдерживаемые источники. Общие журналы Windows и архив evidence.jsonl не должны выдаваться за очищенные.
8. Проверить восстановление резервных копий только в тестовой среде. Реестровая копия не гарантирует автоматическое восстановление всех состояний PnP или Bluetooth.
9. Повторить с переподключением во время предпросмотра, отказом доступа, недоступным местом резервного копирования и прерыванием операции. Неуспешно удалённые карточки должны оставаться в базе.
10. Проверить offline-анализ реальных SYSTEM/SOFTWARE/NTUSER, включая текущий ControlSet002, длинные Unicode-пути и включение привилегий; исходные файлы должны сохранить хеши.
11. Проверить длительный мониторинг, физические подключения/отключения, остановку, повторный запуск и недоступность WMI. Сторонние утилиты и Procmon проверять отдельно, с доступной средой и разрешёнными драйверами.

Артефакты приёмки: версия Windows и приложения, входные идентификаторы, протокол операций, снимки источников до/после, результаты повторного сканирования и восстановления, экспорт отчётов. Непроверенные пункты остаются открытыми, даже если все тесты CI прошли.

### Регрессия: Bluetooth-сопряжение без соединения

Сопряжённый телефон и его Classic/LE-профили могут оставаться присутствующими PnP-узлами после отключения. Одного `CM_Locate_DevNode(..., 0) == CR_SUCCESS` недостаточно для вывода «подключён». Для удалённых Bluetooth-компонентов проверяется `DEVPKEY_DeviceContainer_IsConnected` через `DevGetObjectProperties` для их текущего контейнера; отсутствие или неправильный тип свойства блокирует удаление. Радиомодуль и обычные USB-устройства сохраняют проверку PnP.

На тестовой Windows обязательно проверить четыре состояния: сопряжён и отключён; реально подключён; переподключён после предпросмотра; состояние контейнера недоступно. После удаления проверять отдельно сопряжение, Classic/LE/PnP-узлы, интерфейсы и карточки SQLite. Разрешённый предпросмотр не равен успешному удалению. Причины заблокированных строк записываются в `app.log`, даже если пользователь закрыл предпросмотр без удаления.

## Границы достоверности

- Совпадение устройства между компьютерами не доказывает перенос файлов.
- Буква диска и видимое имя дают косвенную привязку; серийный номер также нужно оценивать вместе с моделью и его качеством.
- Число артефактов не равно точному числу действий человека.
- Проверка evidence.jsonl и печатей сессий не удостоверяет неизменность текущих карточек SQLite или подлинность первоисточников.
- Изолированный файловый куст проверяет операции реестра и логику приложения, но не заменяет PnPUtil, Bluetooth API и доступ к защищённым ветвям рабочей Windows.
