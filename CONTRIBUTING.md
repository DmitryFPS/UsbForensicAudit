# Участие в проекте

Спасибо за интерес к UsbForensicAudit. Прежде чем начать, ознакомьтесь с
[LICENSE](LICENSE): проект распространяется под проприетарной
source-available лицензией; отправляя pull request, вы передаёте
правообладателю неисключительное право использовать предложенные изменения.

## Как предложить изменение

1. Создайте issue с описанием проблемы или предложения.
2. Дождитесь подтверждения, что изменение уместно (для крупных изменений —
   обязательно, чтобы не делать работу впустую).
3. Сделайте форк, создайте ветку от `main`.
4. Внесите изменения, добавьте/обновите тесты.
5. Откройте pull request с описанием: что изменено, зачем, как проверено.

## Требования к коду

- **Windows-only**: основная сборка требует Windows 10/11 и .NET SDK из
  `global.json`. Сборка и тесты: см. [BUILD.md](BUILD.md).
- **Архитектура**: соблюдайте направление зависимостей
  Domain → Application → Infrastructure → Presentation. Новые источники
  артефактов реализуйте через `IEvidenceCollector` (см. README,
  раздел «Расширение системы»).
- **Стиль**: определяется `.editorconfig`. Предупреждения компилятора —
  это ошибки (`TreatWarningsAsErrors`), nullable включён.
- **Тесты обязательны**: CI требует покрытие ≥90%. Новый код без тестов
  не пройдёт quality gate.
- **Зависимости**: restore работает в locked-режиме. При изменении пакетов
  обновляйте lock-файлы (`dotnet restore --force-evaluate`) и не добавляйте
  зависимости без необходимости.

## Коммиты

- Пишите сообщения в стиле Conventional Commits:
  `feat: ...`, `fix: ...`, `docs: ...`, `refactor: ...`, `test: ...`, `ci: ...`.
- Один коммит — одно логическое изменение.
- Язык сообщений: русский или английский, главное — единообразие внутри PR.

## Проверки перед PR

```powershell
dotnet build UsbForensicAudit.sln -c Release
dotnet test UsbForensicAudit.sln -c Release
```

CI дополнительно выполняет аудит уязвимых пакетов и CodeQL — PR с красным
CI не рассматриваются.
