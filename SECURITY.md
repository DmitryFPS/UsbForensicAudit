# Политика безопасности

## Поддерживаемые версии

| Версия | Поддержка |
| ------ | --------- |
| main (последний коммит) | Да |
| Остальные срезы | Нет |

Исправления безопасности вносятся только в ветку `main`.

## Сообщение об уязвимостях

**Не создавайте публичные issue для уязвимостей.**

Сообщайте приватно одним из способов:

1. **GitHub Security Advisories** (предпочтительно): вкладка
   [Security → Report a vulnerability](https://github.com/DmitryFPS/UsbForensicAudit/security/advisories/new)
   в репозитории.
2. Личное сообщение владельцу репозитория: [@DmitryFPS](https://github.com/DmitryFPS).

В сообщении укажите:

- версию/коммит, на котором воспроизводится проблема;
- шаги воспроизведения и условия (права, ОС, конфигурация);
- потенциальное влияние (повышение привилегий, подмена доказательной базы,
  раскрытие данных и т.п.).

Ответ — в течение 7 дней. Просим не разглашать детали до выпуска исправления
(coordinated disclosure).

## Особый контекст проекта

UsbForensicAudit — forensic-инструмент, запускаемый с правами администратора.
Особо критичными считаются уязвимости, позволяющие:

- **подделать или незаметно изменить доказательную базу** (обход hash-chain
  в `evidence.jsonl`, постфактум-правка `audit.sqlite`, подмена отчётов);
- **выполнить произвольный код** через обрабатываемые артефакты
  (вредоносные значения реестра, журналов событий, имён устройств);
- **повысить привилегии** или закрепиться в системе через файлы,
  создаваемые приложением;
- **раскрыть собранные данные** третьим лицам.

Сообщения по этим категориям рассматриваются в первую очередь.

## Автоматические проверки

В CI уже включены: `dotnet list package --vulnerable` (сборка падает при
уязвимых зависимостях), CodeQL-анализ, Dependabot, locked-режим restore
(`nuget.config` + lock-файлы) против атак на цепочку поставок.
